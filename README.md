# GovAssist AI

GovAssist AI is a React → FastAPI → retrieval-augmented government-scheme discovery application. Its knowledge base is the included `Schemes.csv`: 3,400 raw rows become 3,397 canonical scheme records after exact duplicate removal.

## Run the application

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

In another terminal:

```powershell
cd frontend
npm run dev
```

Set `VITE_API_BASE_URL` from `frontend/.env` when needed; see `frontend/.env.example`.

## Installation

1. Create a virtual environment and install dependencies:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Or .venv\Scripts\activate on Windows
   pip install -r requirements.txt
   ```

2. Generate the RAG Index (Requires GPU for optimal speed):
   ```bash
   # Process raw dataset
   python -m src.ingestion
   
   # IMPORTANT: Generate the FAISS semantic index for all 4,858 schemes.
   # This will automatically download BAAI/bge-small-en-v1.5 and utilize CUDA if available.
   python build_index.py
   ```

3. Run the backend server:
   ```bash
   fastapi dev backend/main.py
   ```

## Retrieval evaluation

Run the reproducible benchmark from the project root:

```powershell
.\.venv\Scripts\python.exe evaluation\evaluate_retrieval.py
```

The evaluator uses the persisted `BAAI/bge-small-en-v1.5` embeddings (384 dimensions) and a FAISS `IndexFlatIP` index over 3,397 vectors. It never rebuilds the model or index.

`evaluation/evaluation_queries.json` contains 30 manually curated natural-language queries and real `scheme_id` relevance labels. Labels were selected by reviewing canonical scheme records, not generated by the retrieval system. The evaluator calls the existing `GovAssistPipeline`, compares its actual top-10 retrieved scheme IDs with those labels, and writes a detailed JSON report to `evaluation/results/retrieval_evaluation.json`.

Reported metrics are macro-averaged Precision@1/3/5/10, Recall@3/5/10, MRR, Hit Rate@K, plus measured retrieval latency (mean, median, p95). The per-query report includes expected IDs, retrieved IDs, relevant retrieved IDs, first relevant rank, and reciprocal rank.

### Evaluation limitations

This is a small diagnostic benchmark rather than comprehensive relevance coverage. It uses mostly one manually selected relevant scheme per query, so precision is conservative when other valid schemes are retrieved. Eligibility accuracy is not measured: the dataset does not provide independent applicant-level eligibility labels. Recommendations depend only on the included scheme dataset and are not real-time government information.

## Research reporting summary

- Dataset: 3,400 raw records become 3,397 canonical records after exact duplicate removal.
- Embedding: `BAAI/bge-small-en-v1.5`.
- Vector index: FAISS `IndexFlatIP`, 384 dimensions, 3,397 vectors.
- Retrieval benchmark: 30 manually curated queries with canonical scheme-ID relevance labels.
- Locked baseline: P@1 0.5000, Recall@10 0.9333, MRR 0.6223.
- Best isolated ranking experiment: raw query + BGE/FAISS at K=10 measured P@1 0.6333, Recall@10 0.9333, MRR 0.7109, Hit@5 0.8333, and mean latency 81.37 ms.

These results are from a small manually curated benchmark, not universal system-accuracy claims. The raw-query configuration remains an isolated research experiment; it has not replaced the production profile-aware pipeline. Eligibility accuracy was not measured.
